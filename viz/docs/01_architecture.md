# 01 — Architecture

## Tech stack (fixed — change only via a decision in `04_decisions_and_state.md`)
| Concern | Choice | Why |
|---|---|---|
| Build/dev server | **Vite** + TypeScript | Fast HMR dev server on localhost (ideal for playwright MCP testing); trivial static `dist/` build for later deployment. |
| UI | **React 18** | Component model fits the panel/canvas/selector layout; ubiquitous, low-risk. |
| Graph rendering | **Cytoscape.js** | Declarative `data(...)` → width/color **style mappers** (exactly what the future two-value width+color encoding needs), native undirected edges, **self-loops** (our diagonal), small-graph layouts, stable & well-documented. |
| State | **Zustand** | ~1 KB store for the shared selection state (dataset/tier/entityKind/entity/highlight) touched by many components. No boilerplate. |
| CSV parsing | **Papa Parse** | Node-side, **ingest only** — correctly handles quoted commas in metabolite names. Never shipped to the browser. |
| Lint/format | ESLint + Prettier | Consistency across sessions and sub-agents. |
| Testing | **playwright MCP server** | The only sanctioned test tool. Drive the real dev server. |

Deliberately **not** used: no component/UI kit (hand-rolled minimal CSS — see style doc), no
router (single page), no data-fetch library (static JSON + `fetch`), no chart lib beyond
Cytoscape.


## Data flow
```
metab_processing/  ->  Results/<project>/<dataset>/easy_download/harreman_outputs/
                                                       *.csv,*.json   (SOURCE, read-only)
        |
        |  npm run ingest -- ../Results        (scripts/ingest.mjs, Node + Papa Parse)
        v
public/data/manifest.json
public/data/<id>/dataset.json                  (tiers, entities + ranking metrics)
public/data/<id>/edges/<Tier>.<entityKind>.json  (edges indexed byEntity for O(1) select)
public/data/<id>/nbhd/<Tier>.json                (neighborhood scores, if the run has them)
        |
        |  fetch() at runtime (src/data/loadDataset.ts)
        v
Zustand store  ->  React components  ->  Cytoscape graph
```
The **ingest adapter is the only code that knows the raw file format.** A new source
(SpaceTravLR betadata) gets a *new adapter emitting the same contract* — the app is untouched.
See `05_data_contract.md`.

## The ingest adapter (`scripts/ingest.mjs`)
- Auto-detects the input path: a `harreman_outputs/` dir, an `easy_download/` dir, a
  `<root>/<datasetName>/easy_download/…` tree, or a `<root>/<project>/<datasetName>/…` tree
  (`Results/`, the current source).
- Emits the manifest + per-dataset descriptor + per-(tier,entityKind) edge bundles + per-tier
  neighborhood-score bundles.
- **Never hard-fails on one bad dataset**: an incomplete harreman run becomes an
  `available: false` manifest entry with a reason, which the app shows disabled.
- Tier parentage is inferred from coarse→fine ordering (`Tier1←Tier2←Tier3`). The
  **cell-type-level** parent crosswalk is left `null` (no annotation map available yet).
- Re-run after the data changes. The `harreman` dataset output is committed so a fresh clone
  runs without the source CSVs; other/larger datasets stay local (see `.gitignore`).

## Deployment posture (local-first, deploy-ready)
- `vite.config.ts` sets `base: './'` so a static `dist/` build works from any path / simple
  host. Everything is client-side over static JSON — no server needed. We are **not**
  deploying now, but nothing precludes dropping `dist/` + `public/data/` on a static host later.
